| W11 | 🐞 **BUG — `POST /tasks`, `POST /projects` and `POST /todos` all honor a caller-supplied `id`, and re-posting the same id 500s instead of 409.** Driven through the real `routes.Routes(tm)` mux (`routes/w11_caller_supplied_id_test.go`): `POST /tasks` with body `{"id":"attacker-chosen-task-id","title":"probe task"}` returns `201` with `"id":"attacker-chosen-task-id"` in the response — the server-generated UUID `TaskRow.BeforeCreate` mints is never used, because `task_impl_task.go`'s `CreateTask` never clears `task.ID` before calling `gormstore.TaskToRow(task)`, and the `BeforeCreate` hook only mints `if r.ID == ""` (`gormstore/task.go:50`). Same gap, same shape, in `project.go`'s `CreateProject` (never clears `p.ID`) and `todo.go`'s `CreateTaskTodo` (never clears `todo.ID`) — confirmed by the same probe against `POST /projects` and `POST /todos`. Re-`POST`ing the identical body a second time hits the sqlite/Postgres primary-key unique constraint and surfaces as `constraint failed: UNIQUE constraint failed: probe_tasks.id`, which `routes/errors.go`'s `writeTaskErr` does not recognize (its `errors.Is(err, ErrTaskAlreadyExists)` 409 arm exists but `CreateTask` never returns that sentinel on this path) — so the caller gets an opaque `500 {"error":"task manager store unavailable"}` instead of a clean `409`. This is the exact bug class `mwanachama-backend-agency`'s AG21 (its own board, `documentation/3. implementation/todo_done.md`) fixed for that repo's `Create<Type>` methods after a similar finding (WK17 on `mwanachama-wakala-api`'s board) — same fix shape applies here: clear `.ID` (and confirm `.CreatedAt`/`.UpdatedAt` can't be forged either — `CreateTask` already sets those unconditionally, so only `ID` is exposed) at the top of `CreateTask`/`CreateProject`/`CreateTaskTodo`, before building the row. | 📋 | Found 2026-09-16 by the fleet integration-test sweep, driving the real mux (loophole catalogue #3/#9: a caller-controlled identity field the server should own).
