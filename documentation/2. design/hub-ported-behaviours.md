# Behaviours ported from the hub's copy

The hub's in-tree copy of this module answered twelve things differently from this repository. They are ported here so that the hub can require the tagged module and answer exactly what it answers today. The drift table and the order of work are in [hub-import-drift.md](../3.%20implementation/hub-import-drift.md); this page says what each behaviour is.

| Behaviour | What the module does | Where |
| --- | --- | --- |
| List answers an object | `GET /tasks` answers `{"items": [...]}`, an empty list as `{"items": []}`, with or without `fields`. A bare array is no longer sent. | `task_fields.go` (`TaskPage.MarshalJSON`) |
| A closing move sets the status | A step that names no statuses still sets one: a move into the step `done` or `archive` completes the issue, into `cancelled` cancels it, and a move of a completed or cancelled issue out of them into `to-do` or `in-coming` makes it pending, into `doing` or `in-progress` in progress. A step that names statuses is read as before. Because the status is now set, an issue closed by such a move refuses a priority edit from then on (409). | `models/backlog.go` (`ImpliedStatuses`), `task_move_path.go` |
| Claim with a holder | `claim_task` takes an optional body `{holder, lease_minutes}` and answers the claim with `agent` and `lease_until` when a holder was named. A holder is recorded as the assignee and a lease is written, as `claim_next` does; a blank holder or one over 64 characters claims without a lease; `lease_minutes` goes through the same bounds as `claim_next`. `agent` and `lease_until` are left out of the answer when empty, for both operations. | `task_claim.go`, `task_claim_next.go`, the operation's `body` argument marked `optional` |
| Finish a todo | `finish_task_todo` (`POST /todos/{todoID}/finish`, body `text` and `links`) sets the todo Done as `update_task_todo_status` does and, only if it was set Done, writes one worker Log entry on its issue. A blank text is refused with 400 before anything is written. It answers `{code, state}`. | `todo_finish.go` |
| Add todos to an issue | `add_todos` (`POST /tasks/{taskID}/add-todos`, 201, body `todos`) appends several todos to an existing issue in one call, after the ones it has. `waits_on` counts positions within the list sent. | `task_add_todos.go` |
| One backlog | `GET /backlogs` takes an optional `backlog` (id or name, any case) and answers only that backlog with its steps. An unknown or unseen backlog answers an empty list. | `backlog_access.go` (`ListBacklogsMatching`) |
| Skipped issues of a batch | `next_ready_batch` lists at most `skipped_limit` skipped issues (1 to 50, default 3; anything else is 400) and always counts every one in `skipped_total`. | `task_next_ready_batch.go` |
| Repeating task due dates | A repeating task's read and list carry `next_due_at` (the start of its next period in the schedule's zone; empty when stopped or without a later period), and `last_task_id`, `last_due_at` and `last_done_at` of the newest job it made. They are computed on read, not stored. | `repeating_upkeep.go`, `repeating_last_upkeep.go`, `repeating_store.go`, `models/repeating.go` |
| Working-time clock | `task_timed_out` and `task_caps_nearest` count a worker's time from the first worker Log entry written within five seconds before the latest move into the `in-progress` or `doing` step, that is from the latest claim. An older entry from an earlier attempt no longer starts it. | `task_clock_start.go` (`clockStartTimes`) |
| Shared evidence folder | Two paths under a folder named `documentation/3. implementation/todo/` are not a clash, so `next_ready_batch`, `task_stuck` and `task_file_overlaps` do not report two issues as clashing over it. A code file both name still clashes. | `task_file_overlaps.go` |
| Due time | `due_at` must be an RFC 3339 time on create, and on update when it changed; otherwise 400. | `task_due.go`, `task_impl_task.go` |
| One project create at a time | `CreateProject` holds a process-wide mutex across the name check and the insert, so two concurrent creates of one name make one project and refuse the other with `ErrProjectAlreadyExists`. It does nothing across processes. | `project.go` (`projectCreateLock`) |

The `id` alias for `taskID` in a path, the 409 for a busy store and the optional body of an operation argument are not in this repository: the `dispatch` package of `mwanachama-backend-shared` (v0.3.0, which this module requires) carries them (`dispatch/issue_alias.go`, `dispatch/busy.go`, `Optional` in `dispatch/spec.go`).
